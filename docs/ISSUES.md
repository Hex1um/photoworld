## P0 · 观感与保真

### 1. 视锥内偏暗/雾感 `DONE`

* **症状**：站在原点看，画面比原片暗一层、对比度偏低。
* **排查过程（重要）**：先怀疑雾量，把近景层 `fog` 0.26 → 0.12 → 0.16，
  又给近景壳单独加 1.18× 天光 —— **三者统计值完全一样**（0.495 / 0.172）。
  原因：app 里有**自动曝光**（`world.targetLum`，8 帧内收敛），
  它会把任何光照/雾变化归一化掉。**改光照参数是无效的。**
* **真正的旋钮**：`js/app.js` 里 `targetLum = col.lum × 0.82`（上限 0.55）。
  亮照片因此被压暗约 18%。改成 `× 0.95`、上限 0.62。
* **结果**：渲染均值 **0.573**（原片 0.582）、标准差 0.182（原片 0.204）。
* **证据**：`lum_cmp.png`（左渲染右原片）。
* **残留**：画面右侧有一条竖向接缝/条纹 → 归到第 4 项。

### 2. 视锥外没有照片纹理（只能风格相似）`WONTFIX（信息论限制）`

* **事实**：照片只包含视锥内的信息，视锥外任何"纹理"都是编造的。
* **已试过且更糟**：用照片地面区域做平铺 → 拼布 + 接缝（`tex2_g.png`）。
* **当前做法**：多尺度顶点色噪声（25m/8m/3m/1m）+ 坡面明暗，只保证"风格一致"。

### 17. 两条**已测量并否决**的方案（写下来防止重踩）`DONE（结论：不采用）`

**(a) 深度后处理（边缘重切分 + 双层窄带）在点云路径无收益。**

## 附录 A · 环境坑（踩过就别再踩）

| 坑 | 症状 | 对策 |
|---|---|---|
| `text=True` 解码 | 子进程调用 `tasklist`/`ipconfig` 等在中文 Windows 输出 GBK → `UnicodeDecodeError`，且异常发生在 reader 子线程，主线程只见 `None` → **整轮全 0 分无任何提示** | 收字节，显式 `decode('utf-8'/'cp936','replace')` |
| 批量删除保护 | 连续删到 50 次被拦截 → 评分服务连接被切（`Remote end closed`） | 固定工作目录、只覆盖不删除 |
| 后台进程生命周期 | `(cmd &)` 起在 shell 里的服务，**该次调用结束即被回收** | 与训练同一任务启动，或用桌面临启动器 |
| 并发浏览器端口 | 两个 `multiview` 同时跑抢调试端口，失败时 **stderr 为空** | 全局文件锁 `out/_score/.mv.lock`（>300s 或 PID 不存在即视为陈旧） |
| `ThreadingHTTPServer` + CUDA | 非主线程调 CUDA → 进程直接崩，客户端只见连接被关 | 用单线程 `HTTPServer` |
| `Tee-Object` | PS 5.1 写 UTF-16，文本工具看是"每字符夹空格" | `Add-Content -Encoding utf8` |
| 一次性脚本无断言 | `s.replace` 静默不匹配 → "改了没反应"，浪费整轮验证 | **每次 replace 都带 assert** |
| `rgb` 未定义 | `sem.segment(rgb)` 在 `rgb` 定义之前 → NameError 被 try 吞掉 → **语义从未生效** | 用已定义的变量；`try` 里要 `raise` 或至少 loudly log |

## 附录 B · 仍生效的架构决策

1. **分层**：`near`(视差) / `backdrop`(无视差背景) / `top`(地面层) / `solid`(封闭体) / `ground`(裙边)。
2. **地面层**：只由**语义地面像素**（ground+water+terrain）建，并在**照片足迹打洞** —— 
   视锥内必须是照片本身，视锥外才是程序化地形。
3. **远景层不做断崖剪面**：靠它填近/远交界那条缝（否则山脊上一道亮线）。
4. **俯视 = 飞行状态开关**（`world.showPlan`），靠高度阈值永远切不过去。
