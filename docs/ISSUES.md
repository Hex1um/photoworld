**v3.0.2 追加**：起飞不再全白（v3 不切俯视 LOD + 足迹地板 + 低频起伏）；
天空"大圆圈"确认是照片天空壳，已单独成层并按距离/飞行淡出；穹顶颜色改按纬度取中值去亮斑；
地物改由照片前景的原型驱动；外侧亮度按照片地面色匹配。仍未解决：空中照片壳像投影卡片、
侧看拉丝（正解是投影纹理）。

**未达标（按优先级）**：

1. **山脊 1px 过渡带**：断崖格四角里混着天空像素，逐角插值把天空色拖到轮廓上。
   试过"整格取最近角颜色"，天空那侧被前景色盖住 → PSNR 48.2→29.5dB，已回退。

2. **视锥外地形偏低频**：全景深度的 8 视角低频不一致，近场已强制压到 y=0，

3. **地物是圆锥树**：结构对（转身有林地，不是空坡），但不是照片级。
4. **GLB 体积**：step=4 + q85 = 16MB，需要 Draco/简化才能上 CDN。
5. **扩散地平线与照片地平线未必对齐**：接缝处有高度台阶，目前靠拉色缓解。

**这一轮最值钱的三条教训**（都属于"症状看着像 A，其实是 B"）：

| 症状 | 真实原因 | 定位手段 |
|---|---|---|
| 整屏发灰、像蒙了雾 | 照片壳被 `shellAlpha` 淡成 0（包围盒没外扩，出生点在壳外 0.96m） | probe 出 `shellAlpha=0` |
| 天空被洗白 | 给 900m 天空壳叠了 0.30 的雾（天空壳就是"远处本身"） | 隐藏 backdrop 对比 |
| 某层完全不显示 | 顶点含 NaN / 绕序与背面剔除相反 | 逐层 hide + 检查 `np.isfinite` |

## P0 · 观感与保真

### 1. 视锥内偏暗/雾感 `DONE`

* **症状**：站在原点看，画面比原片暗一层、对比度偏低。
* **排查过程（重要）**：先怀疑雾量，把近景层 `fog` 0.26 → 0.12 → 0.16，
  又给近景壳单独加 1.18× 天光 —— **三者统计值完全一样**（0.495 / 0.172）。
  原因：app 里有**自动曝光**（`world.targetLum`，8 帧内收敛），
  它会把任何光照/雾变化归一化掉。**改光照参数是无效的。**
* **真正的旋钮**：`js/app.js` 里 `targetLum = col.lum × 0.82`（上限 0.55）。
  亮照片因此被压暗约 18%。改成 `× 0.95`、上限 0.62。
* **结果**：渲染均值 **0.573**（原片 0.582）、标准差 0.182（原片 0.204）。
* **证据**：`lum_cmp.png`（左渲染右原片）。
* **残留**：画面右侧有一条竖向接缝/条纹 → 归到第 4 项。

### 2. 视锥外没有照片纹理（只能风格相似）`WONTFIX（信息论限制）`

* **事实**：照片只包含视锥内的信息，视锥外任何"纹理"都是编造的。
* **已试过且更糟**：用照片地面区域做平铺 → 拼布 + 接缝（`tex2_g.png`）。
* **当前做法**：多尺度顶点色噪声（25m/8m/3m/1m）+ 坡面明暗，只保证"风格一致"。

### 3. 地面层与俯视细节无法统一（shader mode 10）`DONE（v2.15.13，默认关闭待观感确认）`

* **目标**：片元级程序化噪声（按世界坐标），让地面视角与 120m 俯视看到同一套细节，

* **根因**：旧 mode 10 GLSL 编译失败（`undeclared identifier`）→ 整站白屏，已撤回。

  编译障碍不复存在。
* **已做（v2.15.13）**：补 `mode == 10` 分支（世界坐标多尺度噪声 + 顶点色留大色相）。

### 17. 两条**已测量并否决**的方案（写下来防止重踩）`DONE（结论：不采用）`

**(a) 深度后处理（边缘重切分 + 双层窄带）在点云路径无收益。**
带内覆盖率不低（coast：6954/64000 px），但 `?dpost=1` vs `?dpost=0` 在 4 图 × 8 机位下
`stripe 2.2455→2.2388`、`voidFrac 0.0135→0.0136`，截图肉眼无差别。原因是斜坡片只在
**三角形连接**时形成，点云不连点；而网格路径本来就有"四角距离比 > 2.6 跳面"的剔除。
→ 结论：模块保留（`js/depthpost.js`，有单测），**默认只在 `?splat=0` 开启**。

**(b) "地面平面置信度"不能当"这张照片有没有可见地面"的判据。**

### 18. 地面放射状拉丝：已定位到图层，但**没有安全修法** `TODO`

### 22. C 圈的"放射长刺"：照片壳在背面被看见 `DONE（v2.15.11）`

- **实测**：长刺消失；`innerVoid -11.4%`、`voidFrac -8.7%`、`lowVoid -4.0%`，

### 23. `stripe` 在"无内容视角"上不可用 `TODO`

同一组 32 机位里，把内容撤掉（`?skip=shell` 或本轮薄壳淡出）后 `stripe` 反而升高

## 附录 A · 环境坑（踩过就别再踩）

| 坑 | 症状 | 对策 |
|---|---|---|
| `text=True` 解码 | 子进程调用 `tasklist`/`ipconfig` 等在中文 Windows 输出 GBK → `UnicodeDecodeError`，且异常发生在 reader 子线程，主线程只见 `None` → **整轮全 0 分无任何提示** | 收字节，显式 `decode('utf-8'/'cp936','replace')` |
| 批量删除保护 | 连续删到 50 次被拦截 → 评分服务连接被切（`Remote end closed`） | 固定工作目录、只覆盖不删除 |
| 后台进程生命周期 | `(cmd &)` 起在 shell 里的服务，**该次调用结束即被回收** | 与训练同一任务启动，或用桌面临启动器 |
| 并发浏览器端口 | 两个 `multiview` 同时跑抢调试端口，失败时 **stderr 为空** | 全局文件锁 `out/_score/.mv.lock`（>300s 或 PID 不存在即视为陈旧） |
| `ThreadingHTTPServer` + CUDA | 非主线程调 CUDA → 进程直接崩，客户端只见连接被关 | 用单线程 `HTTPServer` |
| `Tee-Object` | PS 5.1 写 UTF-16，文本工具看是"每字符夹空格" | `Add-Content -Encoding utf8` |
| 一次性脚本无断言 | `s.replace` 静默不匹配 → "改了没反应"，浪费整轮验证 | **每次 replace 都带 assert** |
| `rgb` 未定义 | `sem.segment(rgb)` 在 `rgb` 定义之前 → NameError 被 try 吞掉 → **语义从未生效** | 用已定义的变量；`try` 里要 `raise` 或至少 loudly log |

## 附录 B · 仍生效的架构决策
