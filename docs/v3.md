# v3 管线：逐像素几何 + 连续曲面 + 扩散外推

> 目标（用户原话）：输入图片 → 视锥内推出每个像素的位置 → 推出 3D 模型 →
> 把视锥 3D 模型补成连续的 → 用扩散模型推出视锥外的地形与地物 → 最后集中着色。
> **视锥内从原点看必须尽量等于原图。**

v2 的在线/LDI 链路在实测里最刺眼的是"幕布""地毯""纸片背面"这三类病，根因是
**单层薄片**：深度只在 518²（或 1540 长边）上算一次，然后所有像素连成一张连续曲面。
v3 换了三件事：几何按**每个像素的世界坐标**建、断崖处用**双四边形**补成连续体、
视锥外**真的用扩散模型生成**再反推深度。

## 一、管线

| 步骤 | 模块 | 做什么 | 关键判据 |
|---|---|---|---|
| 1 | `depth.py` | DA-V2-Large 高分辨率视差 → 米 | 地面带物理锚定优先，不可信退分位双锚点（复用 v2 的 `calib.py`） |
| 2 | `frustum.py` | 每像素 3D → 连续曲面 + 天空壳 | 断崖双四边形；地面按**几何判据**吸附到 y=0；裙边沿射线挤出 |
| 3 | `pano.py` | 照片 → 360° 等距柱状全景 | 已知区（照片投影）**逐像素还原**，其余交 SDXL inpainting |
| 4 | `terrain.py` | 全景 → 8 视角深度 → 极坐标高度场 + 树石 | 视角用 90° 透视（等距柱状图直接跑深度会因拉伸失准） |
| 5 | `shade.py` | 统一太阳/天光 + 接缝拉色 | 光照归一化到"水平面 = 1.0"，视锥内贴图不改 |
| 6 | `bake.py` + `verify.py` | 打包 GLB + **光栅化验证** | 原点 PSNR / SSIM / 重投影误差 |

## 二、三条不变量（v3 的核心设计）

**① 世界系与前端逐字一致**
`y` 向上、地面 `y=0`、相机在 `(0, eye, 0)`、光轴朝 **-Z**。v1 的 `geom.Camera` 用 +Z
朝前，与 `js/glbworld.js` 相反，跨模块拼接时反复出错（"底部尖刺带""整幅放大错位"）。

**② 一切几何修正只沿相机射线做**
沿射线缩放不改变顶点在原点相机下的投影。地面压平（`z → -eye/dir_y`）、裙边挤出、
双四边形重定位，全都建立在这条上 —— 所以"好看"和"像原图"不再互相拉扯。

**③ 颜色走照片 UV，不走顶点色**
视锥内的颜色就是贴图上那个像素本身。顶点色只有 `far / prop / dome` 在用，
它们的 UV 指到贴图底部一条 8px 的纯白条上（`贴图 × 顶点色 = 顶点色`），
因此**不需要改前端渲染器**就能让两类图层共存。

## 三、断崖：双四边形（这一步决定成败）

v2 在深度断崖处**跳过四边形**。后果是从原点看，轮廓上留一圈 1 格宽的洞 —— 黑色，
PSNR 直接掉到 22.7dB（本项目实测）。

v3 对每个断崖格生成**两张**四边形：

* 近端：四角沿各自射线缩到该格最近的深度 → 从原点看显示的是**前景自己的像素**；
* 远端：四角放到最远深度 → 侧移时露出的是**背景**，不是虚空。

两张都只沿射线移动顶点，所以原点视角不变、侧面又有厚度。再给断崖边加裙边（沿射线
后挤 30%），从任何角度都没有"纸片"。

## 四、视锥外：扩散 → 深度 → 地形

1. 照片按真实内参投到 2:1 等距柱状图（1024×512）。已知区只占 **3.5%**（60°×40°），
   其余 96% 是模型要生成的。
2. 生成前把未知区填成"天在上、地在下"的垂直渐变（颜色取照片顶/底缘）。直接留黑或
   留边缘拖影，SD 会照着拖影画出左右镜像的重复地貌（实测）。
3. SDXL inpainting 出全景；已知区**逐像素还原**成原图；左右 6% 列环绕交叉淡化。
4. 全景切 8 个 90° 透视视角，每个视角跑同一套 `depth.calibrate`，反投影成世界点云。
5. 点云 → 极坐标高度场（方位 720 × 对数半径 160，3~600m）→ 网格。
   颜色按方位/仰角从全景采样，所以地貌色来自扩散模型，不是程序化调色。
6. 地物：按方位的"植被感"（绿占比 + 暗占比）撒针叶树/石块，颜色取全景。

### 三个必须记住的坑（都已修）

| 坑 | 症状 | 判据 |
|---|---|---|
| 天空掩码做形态学前不补边 | 天空占比恒 0（`binary_opening` 把首行整行腐蚀掉，"与顶边连通"永远不成立） | 先 `pad(3, edge)` 再 open |
| push-pull 的分母混入"无值"层 | 背景深度全 0 → `exp(0)=1m` → 背景层挤到眼前，PSNR 48→30 | 分母只统计有值部分 |
| 地形先铺进照片区域 | 远景地形盖住山体，PSNR 41→21 | 按方位用**近景层最大半径**挖洞，而不是只统计地面顶点 |

另外两条"看着像雾、其实是别的东西"：

* **整屏发灰** = 照片壳被 `shellAlpha` 淡成 0（包围盒没外扩，出生点在壳外 0.96m），
  不是雾太重；`probe` 出 `shellAlpha=0` 即可确认。
* **天空壳被洗白** = 给 900m 的天空壳叠了 0.30 的雾。天空壳就是"远处本身"，
  v3 资产在 extras 里给 `backdropFog: 0.02`。

## 五、验证：真的光栅化一遍

`verify.py` 用 numpy 写了个 z-buffer 光栅化器（透视校正 UV + 顶点色），把 GLB 里
**真实存在的三角形**投影回原点相机，再与原图逐像素比。不走"用管线自己的深度图反投影"
那种自洽验证 —— v2 的 32 机位指标就栽在这上面（ISSUES §25：世界塌成平地时 8 项指标
几乎不动）。

`worlds/alpine.jpg`（1536×968，step=4，JPEG q85）实测：

| 指标 | 值 | 说明 |
|---|---|---|
| `psnr_core` | **48.2 dB** | 只统计"照片自己定义过的像素"（near + 照片天空壳） |
| `psnr` | 41.2 dB | 全部覆盖像素（含 360° 穹顶补的 0.4% 边角，精度天然低） |
| `ssim` | 0.973 | |
| `coverage` | 99.0% | |
| `reproj` | 2.9e-05 px | 顶点重投影误差 —— 内参/坐标系一致性的硬证据 |

对照：同一张图 v2 的 LDI 资产在原点视角只能做到 22.7dB（轮廓黑洞主导）。

## 六、用法

```bash
# 一张
python pipeline/v3/bake.py worlds/alpine.jpg --out out/v3/alpine

# 批量（每张一个子目录）
python pipeline/v3/bake.py "corpus_test/*.jpg" --out out/v3/all --step 4 --limit 8

# 不跑扩散（没有 GPU / 只想看视锥内）
python pipeline/v3/bake.py photo.jpg --out out/x --no-diffusion
```

产物：`world.glb`（前端 `?glb=` 直接用）、`world.json`（参数+指标，可追溯）、
`pano.jpg`（全景，人工目检）、`origin.png`（原点视角**光栅化结果**）、
`diff.png`、`views.png`（侧/后/俯视联系表）。

成本（RTX 5070 Laptop 8GB）：深度 15s + 全景 30s（20 步 SDXL，CPU offload）+ 地形 5s
+ 打包/验证 80s ≈ **2 分钟/张**，GLB 16MB（step=4）。

前端：`?glb=assets/world-v3-alpine.glb`。v3 资产在 `asset.extras.v3` 里写管线标记/
太阳/包围盒，`app.js` 据此关掉程序化延伸器、把出生俯仰角设成拍摄俯仰角、双面绘制近景层。
