## 怎么读这张表（重要）

1. **本轮的 26 条修复全部在 Python 路径**（`pipeline/` `server/` `worldmodel/` `scripts/` `tools/`），
   浏览器链路 `js/` 与 `index.html` **零改动**（`git diff --stat -- js/ index.html` 为空）。
   所以这张表反映的是"前端现状"，不是本轮改动带来的变化；本轮对前端的唯一影响是
   版本串 2.15.7 → 2.15.8。
2. **与 `docs/acc32b.md` 的数字不可直接比**。那份基线同一批图的 `stripe` 是 1.20~1.60，
   本机是 2.32~3.69；`0116beac` 的 `innerVoid` 基线 0.077、本机 0.678。
   差异来源是**采集条件**（浏览器/GPU 光栅后端/视口/机位参数），仓库自己的纪律就写着
   "指标只能同后端比较"。要跨机器比，必须先固定 `--gl`、分辨率与机位。
3. `0116beac09cf82d5`（黑白雪山）的 void/lowVoid 是**指标失效**，不是世界空了：
   `voidFrac` 统计"与画面主色（clear color）接近的像素"，这张图整体是深灰阶，
   暗部与 clear color 几乎相同 → 大面积误判为空底。看截图能看到内容（只是地面被拉成
   黑白放射条）。这条应当按"指标在单色图上不可用"记档，而不是当失败去优化。
4. 真正需要在下一轮解决的是 `stripe` 全线 >2.0：32 机位里包含 C 圈（r=75，在照片矩形之外），
   那一段是程序化地形 + 世界幕，本来就比照片区域"条纹化"更严重。
