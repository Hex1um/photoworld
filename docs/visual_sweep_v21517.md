## 二、按"能不能修"归类

### 可修（有明确机制，值得做）

1. **地面放射状拉丝** —— 12 张**全部**出现，是画面里面积最大的一处。
   机制已确认：重建层的地面顶点位置是解析解（y=0 射线求交），但 UV 取自照片
   同一块像素，于是贴图沿视线被拉成长条。`?skip=ground` 和 `?groundphoto=0` 都去不掉
   （ISSUES §18）。修法：地面像素改用**世界坐标平铺 UV + 平铺贴图**，或按各向异性做
   mip 偏置。
2. **夜景被渲成白昼**（`1fb9bb00`）—— 代码里 `isNight`（`meanLum < 0.28`）存在但没生效：
   城市夜景的整图均值被大片灯光抬到阈值以上。判据应改用**暗部占比 + 高光稀疏度**
   （夜间照片的直方图是"低谷 + 少数尖峰"），而不是单一均值。
3. **`08_autumn_fg` 的标定被钳到 3.2** —— 远锚（0.786）与近锚（0.925）几乎相同，
   说明"地平线以下的 42~52% 行"落进了树冠而不是远处地面。这类图应显式降级
   （缩小可走范围 / 放大竖直夸张），而不是硬算出一个 p。

### 结构限制（不是 bug，需要换表示或上生成）

4. **侧面/背面只有单层壳的边缘** —— 照片只含视锥内信息，侧后方的"薄板/楔形/悬空布片"
   是单层壳的必然结果。程序化地面能兜住"地上有东西"，但兜不住"那个东西的侧面"。
   这是 ISSUES #13 / P0-1，**唯一根治路径是生成补全**（outpaint / 多视图）。
5. **纵深压缩** —— `01_grass_snowmtn` 的纵深是 5m（草）到 30km（雪山），
   而标定的远锚是 520m，山自然被压到地平线附近。这是"相对深度 + 固定远锚"的
   信息论限制。

### 指标不可信（不要用它判断这些画面）

6. `ca2dd680`（云海）/`0116beac`（黑白雪山）的 `voidFrac` 0.05 / 0.42 都不代表"世界空了"——
   前者是云被当成空底，后者是整幅深灰阶与 clearColor 撞色。§23/§24 已记。

## 三、本轮据此做的修改

- **indoor 判定改看语义构成**（v2.15.17）：四张户外风景（草地雪山 / 山林 / 秋林 / 云海）
  曾被判成 `indoor` → 走 0.6~18m 短基线，整个世界压成 18m 的碗。
  现在 `wall>0.35` 或 `ceiling>0.20 且 sky<0.05` 才算室内；钢琴房（wall=0.545）保持室内。
- 新增 `tools/montage_views.py`：把 6 个代表机位拼成联系表，供后续每次改动做目检。

## 四、建议的下一步顺序

1. 地面放射拉丝（面积最大、机制清楚）；
2. 夜景判据（用暗部占比，别用均值）；
3. 侧后方的"壳边缘"——先做**降级美学**（远处淡出到程序化地形，`?shellfade` 机制已就位），
   再谈生成补全。
