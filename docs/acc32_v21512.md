## 结论：与前一轮**完全同量级**，说明这 21 条修的不是"在线链路的画面"

本轮修的是：照片壳/点云的**资源与生命周期**（F7 显存回收、F10 监听泄漏、F11 tile 泄漏、
F12 加载竞态、F20 blob URL）、**GLB 资产路径**（F3 topHole 双绘、F5 黑带、F13 非索引
primitive、F15 accessor 对齐、F16 死代码、F17 白建点云）、**版本与 UI**（F6 强制重载、
F21 死 UI、F19 字标比例、F14 DPR）。在线 32 机位质检走的是 `?img=` 的同一张照片、
同一套 splat 路径，这些修复大多不在它的覆盖面上 —— 指标不动是**预期**，不是没改。

要验证这批修复，得用它们各自的场景（下面每个都能复现）：

| 修复 | 复现/验证方式 |
|---|---|
| F3 侧视浅灰面 | `?glb=<带 topHole 的 world.glb>&instant=1` 侧转 90°，`?dbg=layers` 看是否还有第二份亮面 |
| F5 资产地面黑带 | 同上，看照片区域之外的地面颜色（改前是黑/深灰带） |
| F6 强制重载 | 打开页面看 Network 是否只加载一次 HTML（改前每个会话多一次整页重载） |
| F7 显存回收 | 连续切换 5~8 个世界，`gl.getParameter(gl.SAMPLES)` 之外用 `performance.memory`/任务管理器看是否持续上涨 |
| F10 监听泄漏 | 进出世界 5 次，`getEventListeners(document)`（DevTools）里 `pointerlockchange` 应恒为 1 |
| F14 DPR | 浏览器缩放到 150% 后拖动窗口，画面应重新清晰 |
| F19 字标比例 | 画廊卡片（`<img>` 有 CSS 宽）进入时的 intro 字标不再拉伸 |
| F21 HUD | 右下角 FPS 有数字（改前恒为「—」） |
