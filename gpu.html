三条路，按画质从高到低

  1. 路线一：本地 GPU 服务（画质最好，需要 NVIDIA 显卡）
    服务端跑 Depth-Anything-V2-Large + LDI 分层，产出的世界是照片级。

    最简做法：下载上面的一键启动脚本，双击它，其余全自动 （起服务、等就绪、开浏览器）。已经放好桌面版也可以直接用。

    高级：手动敲命令 
    python -m pip install torch transformers scipy fastapi uvicorn
cd server && python -m uvicorn app:app --host 127.0.0.1 --port 8100
# 然后打开：http://127.0.0.1:8099/?api=http://127.0.0.1:8100
    权重约 1.3GB，放置方法与镜像下载命令见 pipeline/v2/README.md。
  2. 路线二：浏览器内 WebGPU（需要独显被浏览器认领）
    若上表「GPU 适配器」显示的是 Intel / AMD 核显，说明浏览器把 WebGPU 交给了核显—— 在核显上跑大模型推理通常还不如路线一，甚至不如原来的 WASM 单线程。 让浏览器用上独显：Windows「设置 → 系统 → 显示 → 显卡 → 添加桌面应用」， 加入 msedge.exe（或 chrome.exe）并设为「高性能」，重启浏览器再回本页确认。
  3. 路线三：浏览器内在线链路（零安装，随时可用）
    518² 小模型 + ORT-WASM。山脊与枝叶会糊、边缘易出竖条纹，但不需要任何安装。

常见现象对照

  • 适配器写着 intel，但机器有独显：操作系统没允许浏览器用独显（Optimus 默认策略）。 按路线二改 Windows 显卡设置；--force_high_performance_gpu 这类命令行旗标在多数情况下无效。
  • navigator.gpu 存在但 requestAdapter 返回 null：驱动被禁用或浏览器策略关闭了 WebGPU， 更新显卡驱动，或在 edge://gpu / chrome://gpu 里搜 WebGPU 确认状态。
  • 服务连不上（CORS / 连接被拒）：先确认 http://127.0.0.1:8100/health 能在浏览器里打开； 服务已允许任意来源，剩下的常见原因是端口被占或没用 127.0.0.1 起。
  • v2 依赖显示"缺少权重"：models/da2_large/ 里没有 model.safetensors， 按 pipeline/v2/README.md 的 curl 命令下载（HF 直连常被墙，用镜像）。
